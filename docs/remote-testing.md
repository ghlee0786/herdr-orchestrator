# 원격 시험 PC 운영

## 머신 준비
1. SSH 서버 설치 → 키 인증만 → 방화벽은 지휘 PC 주소만 허용.
2. `hc machine add <이름>` → `hc machine ls` 로 연결 → 신원 확인 명령(`hc exec --on <이름> hostname` 등).
3. 관리자 권한이 필요한 칸은 **별도 머신 이름**으로 등록하고 따로 되살린다.
4. Windows 에서 관리자 SSH 로 Core 를 띄우면 데스크톱 세션을 막는다 → Core 는 그 PC 데스크톱 터미널에서 띄운다.
- SSH · 사설망은 전송 층일 뿐 세션 · 승인 · GUI 를 대신하지 않는다. **머신 등록과 GUI 사용 가능은 따로 확인한다**(로그인된 데스크톱 · 잠금 · 해상도 · 화면 시험은 직렬).
- 호출 PC 의 가드(훅 · 하네스)는 원격 저장소를 검증하지 못한다 — 원격 저장소 쓰기는 그 PC 칸이 그 PC 하네스로.
- 판 맞추기: `hc machine update` 로 원격 Core 판을 지휘 PC 와 맞춘다.

## 원격 PC 한 대 = 칸 셋
| 칸 | 깨우는 예약 | 하는 일 |
|---|---|---|
| 오케스트레이터 겸 작업자 | 2분 | 묶음 파일의 다음 줄 → 없으면 회귀 1번부터 · 시나리오 판 갱신 |
| 감독 | 2분 | 작업자 `hc get` · 화면 · 진행표 · 결과 파일 판정 → 쉼이면 짚기 · 5분 막힘이면 지휘에 · 꺼진 칸 되살림 · 확인 창 풀기 · 작업자의 깨움 예약이 살아 있나 10분마다 확인 |
| UI/UX 감찰 | 5분 | 새 그림에서 레이아웃 비율 · 잘림 · 넘침 · 겹침 · 테마 · 어려운 말 → 결과 파일 · 지휘 |

- 세 칸 모두 그 PC 스페이스의 작업 탭 안에 늘 띄워 둔다. 지휘가 `hc run --on <머신>` 으로 띄우면 원격 칸의 부모는 지휘다(원격 → 지휘 보고가 그 길로만 간다).
- 깨움 예약(Cron)은 그 세션에만 산다 → 재개 · 재부팅 직후 첫 걸음으로 다시 건다.
- 원격 스페이스 지킴이: `hc exec` 로는 앱 배치가 0 으로 보인다 → 그 PC 사용자 세션의 예약 작업이 배치를 읽고, 달라졌으면 묻지 않고 되살린다. 사용자 입력이 60초 안에 있었으면 창을 건드리지 않는다. 그림은 가린 사본만 남긴다.

## 앱 켜는 길
- `hc exec` 나 칸 셸의 자식으로 켜지 않는다 — 명령이 끝나면 앱이 같이 죽어 결함으로 오판된다.
- 켜는 길은 셋뿐: `hc run --bg --outlive-parent --on <머신>` · 사용자 세션 예약 작업 · 현장 칸 자기 셸에서 분리 실행.
- 개발 PC 에서는 시험 앱을 띄우지 않는다.

## 묶음(인계) = 대본 하나
- 묶음 = 파일 하나(`templates/bundle.md`): 목적 · 근거 · 규칙 경로 · 번호 · 허락 범위 · 허락 밖(멈춤) · 계정 순서 · 시한 · 걸음 · 끝 조건 · 보고 꼴 · 결과표 경로.
- 걸음마다 판단하지 않는다. **대본이 걸음을 돌며 그림 · 로그를 쌓고 끝에 한 번 판정한다.**
  - 기다림은 고정 sleep 대신 요소가 뜰 때까지(상한 초).
  - 누르기는 요소 이름이 기대 글과 맞고 앱 창 안일 때만.
  - 서버 쪽 준비(계정 · 자료)는 API 대본으로 미리.
  - 두 PC 짝 걸음은 신호 파일로 서로 기다린다.
  - 대본 함수는 Verb-Noun 이름 · 이름 검사 · 마른 실행 뒤 실제 실행 · PC 마다 모아 재사용.
- 걸음마다 그림 + 로그 줄 · 시각은 서버 시각. 큐 파일에는 줄마다 상태 칸(할 것 · 하는 중 · 끝 · 막힘)과 GO 필요 표시.
- 쉼 없애기: 대본이 도는 동안 다음 대본을 짠다. 지휘는 **두 묶음 앞까지(30분~2시간 분량)** 넣어 둔다. 지금 판으로 되는 걸음은 새 판을 기다리지 말고 지금 한다.
- 보고 꼴: `[묶음 시작]` · `[결함 후보]` · `[요청]` · `[막힘]` · `[묶음 끝] + 결과표`.

## 안 하고 기다리지 않기
| 멈추던 까닭 | 막는 규칙 |
|---|---|
| 턴이 끝나고 아무도 안 깨움 | 되풀이 예약으로 스스로 깸 · 재개 직후 예약 다시 걸기 · 감독이 예약 확인 |
| GO 를 기다림 | 5분 상한 · 허락된 걸음은 그냥 |
| '할 일 없음' | 묶음 끝 = 회귀 1번부터 · 지휘가 두 묶음 앞까지 넣어 둠 |
| 로그인 · 인증 동의 창 | 로그인 표준 대본(동의 [허용] → 다른 길) · 로그인 창 3분이면 대본 |
| 칸 상태만 보고 '정상' | `hc get` 상태 · 화면 그림 · 진행표로 판정 |
| 짝 PC 기다림 | 지휘가 시각을 박고 기다리는 쪽은 그 사이 혼자 할 걸음 · 신호 파일 |
| 뒤 대본 도는데 표시 없음 | 뒤 대본이 진행표를 8분마다 저절로 고침 |
| 사람 손 | 2분 기다림 되풀이(T-5) |
| 긴 턴에 지시가 쌓임 | 한 턴 10분 상한 |
| 계정 한도 | 한도 상태 파일 · 사람 로그인 청 · 바꾼 뒤 옛 한도 창 Esc → 재개 글 |

## 시나리오 판(필수)
- 파일 `results/scenario-board.md` — 틀은 `templates/scenario-board.md`.
- 맨 위 고정 양식: `갱신 hh:mm · 완료율 nn% (완료 n / 전체 n) · 미진행 n · 진행 n · 완료 n`.
- 시험 하나 끝날 때마다 ○ 를 옮기고 지휘에 `[판] 번호 · 완료 · 결과` 한 줄.
- 30분마다 `[판 30분] 완료율 nn% (완료 n / 전체 n) · 이전 대비 완료 +n · ±n%p · 지난 30분 끝난 번호`.

## 화면 판정
`tools/screenwatch.ps1` — 화면이 그대로인 분 · 로그인 창 · 인증 동의 기다림 · 앱 응답을 한 줄로.
화면이 같아도 진행표가 10분 안에 바뀌면 일하는 중으로 본다(창을 열고 바로 닫는 걸음 · 읽기 걸음).

## 자리 등록부 · 작업 기록
- 시험 자리(PC · 서버 · 판 · 담당 칸 · 쓰임) 정본 한 장(T-1). 자리를 정하기 전에 읽는다.
- 작업마다 기록 파일: workId · 총괄 · 작업자 · 레인 · 지시서 · 끝 조건 · 허락 필요 · 상대 전달.
