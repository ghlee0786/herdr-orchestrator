# 칸 역할

모델 · 강도는 프로젝트 설정(`roles`)으로 정한다. 기본값: **분석 · 리뷰 · 총괄 · 결정 = high, 구현 · 시험 · 문서 · 창구 = medium**. 사용자가 프로젝트마다 다르게 정했으면(예: 전부 medium) 그 원문이 앞선다.

| 칸 | 하는 일 | 하지 않는 일 | 기본 강도 | 상주 |
|---|---|---|---|---|
| 사용자 창구 | 사용자 말 원문 기록 · 지시 장부 · 원문 그대로 전달 · 결정 대기 목록 · 사용자에게 올리기 | 작업 지휘 · 제어 글 받기 | medium | 상주 |
| 총괄 | 요청을 단계 · 맡은 칸 · 끝 근거로 쪼갬 · 레인 배정 · 빌드 차례 · 상시 루프 · 감시 경보 처리 | 직접 큰 구현 | high | 상주 |
| 구현 칸 | 자기 레인에서 빨강 → 초록 · 커밋 · 준비됨 보고 | 남의 레인 · 병합 | medium | 필요한 만큼 |
| 리뷰 칸 | 새 맥락에서 병합 전 리뷰(정확성 · 보안 둘) · 사용자 원문 대조 · 결과 파일 | 구현 파일 고치기 | high | 부름 |
| 결정 매니저 | 갈림길을 사용자 결정 패턴으로 결정 · 기록 | 사용자 몫 결정 · 파일 쓰기(기록 외) | high | 상주 |
| 설계 칸 | 현재 상태 · 방향 · 기능 설계 · 로드맵 · 질문 목록 | '구현하지 않는다' 결론 · 다른 총괄 지휘 | high | 부름 |
| 병합 · 키트 칸 | 빌드 자리 쥠 · 묶음 검사 · 병합 · 판 올림 · 키트 · 같은 판 설치기 · release | 규칙 밖 push | medium | 상주 |
| CI/CD 칸 | CI 통과 → 배포 가지 PR → CD 배포 → 실제 확인 | CI 도는 중 push · 고치지 않은 재실행 | medium | 선택 |
| 연락 칸 | 다른 프로젝트 총괄과 협의 문서로 계약 맞춤 | 남의 창구 · 작업자에게 직접 보내기 | medium | 선택 |
| 원격 시험 지휘 | 원격 PC 묶음 배분 · 두 묶음 앞까지 넣어 둠 · 시각 맞춤 · 결함 번호 · GO | 원격 화면 직접 조작 | medium | 상주 |
| 원격 오케스트레이터 겸 작업자 | 묶음을 받아 그 PC 에서 스스로 끝까지 · 시나리오 판 · 결과표 | 기다리기만 하기 | medium | 상주 |
| 원격 감독 | 같은 PC 작업자 화면 · 진행표 판정 · 쉼 짚기 · 꺼진 칸 되살림 · 깨움 예약 확인 | 시험 대신 하기 | medium | 상주 |
| 원격 UI/UX 감찰 | 시험 그림에서 비율 · 잘림 · 넘침 · 겹침 · 테마 · 어려운 말 | 앱 조작 · 설정 바꾸기 | high | 상주 |
| 감사 칸(선택) | 하루 한 번 '끝' 주장과 증거 대조 | 고치기 | high | 부름 |

## 상주 · 부름 · 칸 수
- 분석 · 리뷰 · 설계 · 감사는 부를 때마다 새 맥락으로 띄우고 결과 파일을 받은 뒤 닫는다. 같은 종류 일이 하루 3건을 넘으면 그날만 상주로 둔다.
- 스페이스 하나에 에이전트 칸 10 이하 · 구현 칸은 빌드 자리 + 1 이하.
- 강도는 실제 CLI 에 걸린 값을 확인한다(`/effort` 가 전역 기본에 남을 수 있다). 역할을 바꾼다고 권한 생략 모드를 새로 켜지 않는다. 아직 검증하지 않은 새 모델은 시험 칸에 쓰지 않는다.

## 결정 매니저 헌장
- 읽기 전용. 사용자의 결정 패턴으로 고른다: 추천안이 기본 · 요구 문서가 대전제 · 바깥 요청은 '잘못 알고 한 것' 일 수 있다고 보고 확인 · 필요 최소 · 보안은 보수적으로.
- 사용자에게 넘기는 다섯 갈래: ① 되돌릴 수 없는 바깥 영향 ② 현장 사실(사람만 앎) ③ 기존 사용자 결정과 충돌 ④ 큰 범위 확대 ⑤ 대등한 두 안.
- 꼴: `[결정 요청 id] 질문 · 안 · 근거` → `[결정 id] 채택 <안> · 까닭 · 패턴` / `[사용자 몫 id]`. 기록은 `templates/decision-log.md`(jsonl 열 이름 포함). 늘 총괄 한 창구를 거친다.

## 사용자 창구
- 사용자에게 올리는 것은 네 갈래만: 시킨 일 끝 · 막힘 / 사용자가 정할 것 / 보고와 실제가 다름 / 병합 · 배포. 다섯 줄 안.
- 결정 대기 목록(물은 것 · 언제 · 답)을 들고 있다가 사용자가 오면 한 번에 묻는다. 같은 것을 두 번 묻지 않는다.
- 사용자 원문으로 새 규칙이 생기면 맞는 갈래 파일의 「덧」에 원문 그대로 더한다(지우지 않음).

## 설계 칸 산출물
`00-current-state` · `10-direction` · `20-feature-<이름>` · `30-roadmap` · `QUESTIONS` · `LOG`. 굳은 설계는 하네스 문서(PRD)로 올리고, 다른 총괄에게는 스펙 질문만 직접 보낸다.

## 공통
- 칸은 스페이스의 탭 안에만 띄운다. 일이 끝난 칸은 인계 메모(`templates/handoff.md`) 뒤 정리한다.
- 깨어나면 첫 걸음: 목표 파일(`templates/goal.md`) · 규칙 · 자기 대기열을 읽고, 상태는 기억이 아니라 산출물로 확인한다.
- 한 턴은 10분 안에 끊는다. 긴 대본은 뒤 칸에 두고 `hc wait` · 끝 알림으로 잇는다.
- 주기 감시는 LLM 칸이 아니라 대본(감시견)이 한다 — 한도에 걸리면 감시도 같이 멈추기 때문이다. 원격 PC 안의 감독 칸은 예외로 두되, 그 칸의 깨움 예약도 감시견이 확인한다.
