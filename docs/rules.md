# 공통 규칙

프로젝트에 상관없이 적용한다. 프로젝트 고유 규칙은 덧 파일(`rules.<프로젝트>.md`)로 두고 여기를 고치지 않는다.
규칙을 더할 때는 사용자 원문을 함께 적는다(원문이 규칙의 근거). 새 규칙은 맞는 갈래 파일의 「덧」에 더하고 지우지 않는다. 프로젝트 고유 규칙은 근거(사용자 원문 · 사건)가 있는 것만 모으고 새로 지어내지 않는다.
받은 칸은 끝 보고에 지킨 번호를 적는다.

## G 공통
- G-1 **사용자 원문이 가장 위** — 원문 > 프로젝트 규칙 > 역할 규칙 > 칸 판단. 전달은 원문 그대로 인용.
- G-2 근거 문서가 있으면(요구사항 · 명세) 지시 · 보고에 근거 절 번호를 붙인다.
- G-3 결함이라 말하려면 증거 둘(로그 · 그림 · 시험). 그 전엔 '후보'.
- G-4 운영 환경 쓰기 0. 쓰기 시험은 시험 서버에서만 · 시험 표지 · 원복.
- G-5 자격 · 비밀 값은 명령 · 글 · 문서 · 그림에 0.
- G-6 **허락 범위는 프로젝트 설정 `approvals` 로 정한다.** 기본:
  - 묻지 않음: 목적 · 계획대로 끝난 레인(커밋 · 저장소 시험 초록 · 리뷰 통과)의 커밋 · 병합, 사용자가 미리 허락한 가지의 push · 태그.
  - 따로 허락: 배포를 부르는 병합(예: 운영 · 원격 시험 서버로 CD 가 도는 가지) · 라이브 교체 · 현장 설치 · 운영 쓰기 · 지우기. 허락은 그 범위에만.
- G-7 할 수 없으면 할 수 없다고 쓴다. 고치지 않고 '통과' 로 적지 않는다.
- G-8 **사람에게 꼭 묻는 일곱 갈래**: 강제 push · 기록 고쳐 쓰기 / 충돌 / 비밀 노출 의심 / 공개 범위 변경 / 라이선스 / 계정 · 권한 / 저장소 삭제. 하네스 경계가 막으면 우회하지 않고 막힌 줄을 그대로 보고한다.
- G-9 결과가 달라질 때만 묻는다. 지시에 가장 맞고 나중에 바꾸기 쉬운 쪽을 고르고 끝 보고에 「분기점 · 고른 것 · 까닭」.

## H 운영
- H-1 일을 시킬 때 「규칙 파일 + 걸리는 번호」 와 「업무」 와 「끝 근거」 를 같이 보낸다.
- H-2 사용자 지시는 지시 장부에 한 줄(받음 → 진행 → 끝 · 증거 칸)로. 증거 칸이 비면 '끝' 으로 옮기지 않는다. 약속 시각은 기한 칸에 적고, 기한이 지나면 묻기 전에 「안 됨 · 까닭 · 새 기한」 으로 먼저 올린다.
- H-3 지시 차례: 사용자 원문 > 창구(사용자 전달) > 총괄 · 지휘 > 감독. 엇갈리면 위를 따른다.
- H-4 GO(허락) 기다림 상한 5분. 넘으면 읽기 · 허락된 걸음은 그냥 하고, 나머지는 건너뛰고 [막힘] 한 줄.
- H-5 쉼 기준은 설정 `idle_min` 으로(기본: 원격 작업자 2분 · 총괄 6분 · 일 남은 칸 10분). 넘으면 깨운다. 30분 안 두 번이면 사용자에게 보고하고 사건 장부에 적는다. 대기열에 「대기(…)」 로 적은 칸 · 일부러 멈춤 · 사용자 답 기다림은 빼는 목록.
- H-6 계정 사용 한도로 멈춘 것은 '쉼' 과 따로 센다 — 깨움 셈에서 빼고, 한도 상태 파일(`templates/limit-state.md`)에 적고, 그 PC 로그인을 사람에게 바로 알린다. 크레딧 전환은 사용자 몫이라 누르지 않는다.
- H-7 판정은 칸 겉모습이 아니라 결과로: `hc get` 상태 · 화면 그림 · 진행표 시각 · 결과 파일. Herdr 의 `live` · `idle` · `done` 은 세션 상태일 뿐 '일이 끝났다' 의 증거가 아니다.
- H-8 쓰지 않는 칸은 정리한다 → [recovery.md](recovery.md) 「칸 닫기」. 두 시간마다 훑는다.
- H-9 계정 · PC 가 바뀌어도 같은 대화 · 같은 레인으로 잇는다(새로 시작 0 · 멈춘 목표를 새 목표로 복제 0). 재개 글은 `templates/resume-prompts.md`.
- H-10 **실패 상한**: 실패는 원인별로 센다(설정 `fail_cap`, 기본 3). 원인이 다르면 합치지 않는다. 같은 원인은 고칠 근거가 있을 때만 다시 시험하고 상한에서 멈춰 근거를 보고한다. 고치지 않은 재실행 · 기록 지우기 · 횟수 초기화 · 이름 바꾸기 금지.
- H-11 **끝 보고 재검증**: 커밋이 그 가지에 실제로 있나 · 시험이 그 커밋에서 돌았나 · 리뷰의 BLOCKER/MAJOR 가 닫혔나 · 병합분이 현재 판에 들었나(`git branch --contains`). 종료 코드 0 이어도 건너뜀 · 필수 누락 · 다른 커밋이면 통과가 아니다. '거절 · 취소됨' 으로 돌아온 명령도 실제로 돌았을 수 있으니 흔적을 본다.
- H-12 공용 자원(공유 서버 · VM · 시계)을 내리거나 재시작하기 전에 지금 붙어 일하는 다른 시스템이 있나 본다. 있으면 그 총괄과 맞추고, 없으면 그냥 한다.
- H-13 Git 은 하네스 명령으로만. 기존 레인에서 잇는 것과 `start --from`(그 가지에서 새 레인)은 다르다. 같은 저장소 루트에 되살린 여러 대화는 읽기 · 조율만 하고 고치는 것은 레인에서. git 은 인증 창이 뜨지 않게 돈다.
- H-14 **시한 있는 임시 변경은 세션 밖 원복 고리와 함께** 켠다(기한 · 취소 파일 · 원복 뒤 다시 읽기 · 알림). 한도 · 재시작으로 세션이 멈춰도 원복된다.
- H-15 **되돌릴 수 없는 일 관문**: 현장 쓰기 · 지우기 · 전환은 관문 표(무엇 · 왜 · 허락 · 되돌림 · 확인) 빈칸 0 일 때만. 지우기는 「그 경로를 쥔 프로세스 0 · 참조 0」 을 읽은 출력이 있어야 한다.

## C 코드 · 디자인
- C-1 새 화면은 디자인 컨셉 · 테마 토큰을 먼저 읽고 맞춘다(라이트 · 다크 둘 다).
- C-2 화면 글은 쉬운 말. 설명은 '?' 말풍선.
- C-3 고칠 때 고치기 전 실패(빨강) → 고친 뒤 통과(초록) 증명을 같이 낸다.
- C-4 사용자가 정한 동작은 자동 시험으로 박아 다른 레인이 깨지 않게 한다.
- C-5 판 올림 레인의 끝 = 같은 판 설치기 + 설치 검증 결과표.
- C-6 코드는 목표에 필요한 최소만 · 바꾼 줄은 모두 요청으로 이어진다 · 자기 변경이 만든 안 쓰는 코드만 지운다.

## T 시험
- T-1 시험 자리(PC · 서버 · 판 · 담당 칸 · 쓰임)는 자리 등록부 한 장이 정본이다. 자리를 정하기 전에 읽고, 있는 자원을 먼저 쓴다.
- T-2 두 쪽이 오가는 기능은 두 PC 동시로(한 PC 계정 바꾸기로 대신하지 않음).
- T-3 **가짜 장비 시험 0.** 실제 장비 · 실제 데이터 흐름으로만. 모자라면 그 걸음을 멈추고 결정 요청. 중계 층 대역(시뮬레이터가 아닌 실제 중계 서버)은 가짜가 아니다.
- T-4 회차 시작에 시계 맞춤 · 결과 시각은 서버 시각.
- T-5 사람 입력이 잡히면 2분 기다리고, 그때도 사람이 쓰면 또 2분 — 사람 입력 없는 2분이 오면 진행.
- T-6 승인 · 허락이 나면 1분 안에 실제 동작(열기 · 실행)까지 확인. 거절성 오류는 30초 뒤 1번 더.
- T-7 시나리오 판: 시험 하나 끝날 때마다 갱신 · 30분마다 보고(완료율 · 이전 대비).
- T-8 묶음이 끝나면 1번부터 회귀 · 할 일이 바닥나면 지휘에게 새 시나리오 청.
- T-9 시험 뒤 정리: 띄운 프로세스 · 시험 자료 · 바꾼 설정 원복 · 「만든 것 · 지운 것 · 남긴 것」 보고.
- T-10 **실장비 안전**: 저장된 설정만 쓰고 설정 바꾸기 0 · 다른 사람이 쓰는 중이면 멈춤 · 명령 오류 3번 이어지면 멈춤 · 끝에 원위치 · 앞뒤 상태 기록.
- T-11 **시험 꼴 = 운영 꼴**: 단위마다 자기 서버 · 다른 단위는 연동으로만 보인다. 남의 데이터를 손으로 만들거나 임의 시험 개체를 새로 만들지 않는다. 한 PC 에는 한 번에 한 꼴만 깔고, 꼴을 바꾸는 시간은 실측해 적는다.
