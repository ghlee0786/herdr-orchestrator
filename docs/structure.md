# 구조

## 도구 넷
| 도구 | 맡는 일 | 맡지 않는 일 |
|---|---|---|
| **Herdr Core (`hc`)** | 실제 세션: 칸 띄우기(`hc run`) · 상태(`hc get` · `hc ls`) · 기다리기(`hc wait`) · 글 보내기(`hc send`) · 화면 읽기(`hc read`) · 키(`hc keys`) · 끊기(`hc interrupt`) · 그림 넣기(`hc put`) · 원격 파일(`hc file read/write/edit --on`) · 원격 명령(`hc exec --on`) · 원격 머신(`hc machine add/ls/login/update`) | Git · 판단 |
| **Herdr App** | 스페이스 · 탭 · 칸을 화면에 보여 줌 · 배치 명령(`space.new` · `pane.split` · `terminal.keep`) · 원격 머신 화면 | 일 배분 |
| **Pilot(하네스)** | 저장소 안 `harness/` — 레인(worktree) 격리 · 묶음 검사 · 병합 · push · 정리 · 위험 git 명령 막기 | 칸 관리 |
| **Orca(선택)** | 화면 · 작업공간만 | 같은 작업자를 hc 와 겹쳐 지휘하기 |

- 하네스는 저장소마다 `harness/` 로 깔리고, 원본은 별도 저장소에서 판을 올려 배포한다. Git 쓰기는 하네스 명령(start · check · accept · batch · push)으로만 한다.
- Orca 를 함께 쓰면 Orca 는 화면만 맡는다. 이미 Orca 에서 돌던 Run 메일함 · 무거운 검사 자리는 주인을 넘겨받기 전까지 그대로 두고, 같은 칸을 Orca dispatch 와 `hc` 가 동시에 지휘하지 않는다.

## 세 가지 이름을 섞지 않는다
| 이름 | 무엇 | 바뀌나 |
|---|---|---|
| App 의 space · tab · pane id | 화면 자리 | 배치를 다시 세우면 바뀜 |
| hc 터미널 주소(`t7`, `머신/t7`) | Core 의 칸 | Core 재시작 · 복구 때 바뀔 수 있음 |
| 대화 id(sessionId) | 에이전트의 대화 기록 | 바뀌지 않음 — 이어 하기의 유일한 열쇠 |

- 주소는 회차마다 `hc ls` · `hc get` 에서 **이름**으로 찾고, 보내기 전에 이름 · 대화 id 표지(`original.session` 라벨)를 대조한다.
- 칸 장부(이름 · 탭 · 머신 · cwd · 대화 id · 모델 · effort · 대기열 파일)를 하나 두고 복구 · 정리 · 감시가 모두 그것을 읽는다 → [recovery.md](recovery.md).

## 칸 구조
```
사용자
 └─ 사용자 창구 ── 원문 기록 · 전달 · 결정 대기 목록 · 답
총괄(프로젝트마다 하나)
 ├─ 구현 칸 N          레인 안에서 고침 · 빨강→초록 시험
 ├─ 리뷰 칸(부름)      새 맥락 · 정확성 / 보안 · 고치지 않음
 ├─ 결정 매니저        읽기 전용 · 사용자 결정 패턴으로 고름
 ├─ 설계 칸(부름)      현재 상태 · 방향 · 기능 설계 · 로드맵
 ├─ 병합 · 키트 칸     빌드 자리 · 묶음 검사 · 병합 · 키트 · 설치기 · release
 ├─ CI/CD 칸(선택)     CI → PR → CD → 실제 확인
 ├─ 연락 칸(선택)      다른 프로젝트 총괄과 협의 문서로만
 └─ 원격 시험 지휘 ─┬─ 원격 PC 1: 오케스트레이터 겸 작업자 · 감독 · UI/UX 감찰
                    └─ 원격 PC n: …
감시견(대본 · LLM 아님) ── 이상을 총괄에게, 10분 뒤에도 그대로면 창구에게
다른 팀 총괄 — 같은 꼴 · 서로는 총괄(또는 연락 칸)끼리만 말함
```

## 정보가 흐르는 길
| 무엇 | 어디로 |
|---|---|
| 사용자 말 | 창구가 원문 장부(`inbox`) · 지시 장부에 적고 원문 그대로 총괄에 |
| 총괄 · 지휘의 답 | 프로젝트 설정 `answer_route` 대로 — `file`(답 파일 한 줄, 창구가 읽음) 또는 `send`(총괄 → 자기 프로젝트 창구에 `hc send`). 다른 프로젝트 창구로는 보내지 않는다 |
| 작업 지시 | 총괄 → 칸: 「규칙 파일 + 번호」 + 「업무」 + 끝 근거 |
| 칸의 지금 상태 | 칸별 대기열 파일(`templates/queue.md`) |
| 결정 | 총괄 → 결정 매니저 `[결정 요청 id]` → `[결정 id] 채택` · 사용자 몫은 창구의 결정 대기 목록 |
| 다른 프로젝트 | 총괄(연락 칸) ↔ 상대 총괄. 계약 변경은 커밋(sha)마다 한 번 · 받는 쪽 · 시각 기록 · 같은 sha 다시 보내지 않음 · 남의 작업자 직접 지휘 0 · 맞물리는 계약은 협의 문서 합의 뒤 착수 |
| 원격 시험 | 지휘 → 원격 PC: 묶음 파일 하나 / 원격 → 지휘: 결과 · 막힘 · 30분 판 보고만 |
| 멈춤 사건 | 사건 장부 → 총괄이 갈래 · 조치 · 규칙 반영(선순환) |

## 칸 띄우기 표준
- `hc run --bg --keep --outlive-parent --parent <총괄> --name <이름> --label where=<스페이스/탭> -- <에이전트 명령>` — `--no-parent` 금지 · `HC_TERMINAL_ID` 를 지우지 않는다.
- 첫 업무는 `run` 에 같이 넣는다(부팅 중 보낸 글은 빠질 수 있다). `first_message.sent` 를 확인하고, 실패면 화면부터 읽는다.
- 띄운 직후 `hc ls` 의 `where` 로 탭 안인지 본다. 비었으면 닫고 다시 띄운다.
- 칸 수: 스페이스 하나에 에이전트 칸 10 이하 · 구현 칸은 빌드 자리 + 1 이하(칸 하나 ≈ 메모리 1.5GB, 실측해 설정에 적는다).

## 글 보내기 원칙
- 15줄 넘는 내용은 파일로 쓰고 경로만 보낸다. 그림은 절대 경로(`hc put` 또는 경로)로 보내고 받은 쪽이 실제로 열었는지 본다.
- 기다릴 때는 폴링 대신 `hc wait`(`--children any|all` · `--output`)를 쓴다.
- 상태가 `blocked` 면 사람이 필요한 것이다 — `send --force` 로 확인 창을 넘기지 않는다. 사람이 입력 중이면 send 는 그 초안을 기다린다(`draft_wait`). 끼어들지 않으려면 `--if idle`.
- `timeout` · `unknown` 은 다시 실행할 근거가 아니다. `accepted` 는 '받았다' 일 뿐 '읽었다' 가 아니다 — 결과는 산출물로 본다.
- 원격 칸은 **자기를 띄운 칸(부모)에게만** 보낼 수 있다. 원격 → 로컬은 `<core>/<주소>` 꼴로, 그것도 막히면 결과 파일에 쓰고 지휘가 5분마다 읽는다.
- 그 PC 명령은 `hc exec --on <머신>`(60초 안에 끝나는 것만 · 앱 띄우기 금지 → [remote-testing.md](remote-testing.md)).

## 함정(실측)
- 원격 칸은 로컬 칸을 부모로 둘 수 없다. 원격은 로컬 파일을 못 읽으니 대기열 · 지시는 글로 실어 보내고, 원격 폴더는 `--add-dir` 로 넣는다.
- Git Bash 는 `/exit` 같은 글을 경로로 바꾼다 → 칸 종료는 `hc keys <칸> ctrl+c` 두 번.
- PowerShell 5.1 은 JSON 인자를 쪼개고 한글 출력이 깨진다 → 파일로 넘기고 UTF-8(BOM) 로 쓴다. 대본 함수 이름이 기본 별칭과 겹치면 사고가 난다 → Verb-Noun 이름 + 이름 검사.
- `hc exec` 는 화면에 로그인한 사용자 세션 밖에서 돈다 → 데스크톱 · 앱 배치를 읽거나 GUI 를 켜는 데 쓰지 않는다.
