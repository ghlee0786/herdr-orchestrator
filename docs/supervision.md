# 감독 · 멈춤 막기 · 선순환

## 누가 깨우나 — 한 곳으로
깨우는 쪽이 둘이면 겹쳐 깨운다. 프로젝트 설정 `wake_owner` 로 하나만 정한다.
- `lead`(기본): 감시견 경보는 총괄이 받아 깨운다. 창구는 감시 · 재촉을 하지 않는다.
- `desk`: 사용자가 창구에게 감독을 시킨 프로젝트. 창구가 감시 대본을 돌리고 총괄은 깨우지 않는다.
- 원격 PC 안은 그 PC 의 감독 칸이 깨운다(지휘 · 창구는 그 PC 작업자를 직접 깨우지 않고 감독 칸에 근거 한 줄).

## 감시견(대본 · LLM 아님)
주기 감시는 대본이 한다 — LLM 칸에 맡기면 한도에 걸릴 때 감시도 같이 멈춘다.
- 주기 1분(메모리가 모자라면 5분). 상태는 `hc get --json` 의 `status`(idle · working · done · blocked · error)를 먼저 보고, 화면 글은 보조로만 쓴다.
- 잡는 것:

| 경보 | 뜻 |
|---|---|
| `BLOCKED` · `ERROR` | 확인 창 · 오류 — 사람이 필요하면 사람에게 |
| `OVERDUE` | 지시 장부의 기한이 지남 |
| `CLAUDE_EXITED` | 칸은 살아 있는데 에이전트 프로세스가 없음(셸만 남음) |
| `CORE_RESTART` | `hc server status` 시작 시각이 바뀜 → 복구 마른 실행 |
| `IDLE_WITH_WORK` | 대기열에 일이 있는데 `idle_min` 넘게 쉼 |
| `SCREEN_FROZEN` | 화면이 15분 그대로 |
| `TAB_MISSING` | 칸이 탭 밖(`where` 비었음) |
| `REMOTE_IDLE` | 원격 작업자 쉼 |
| `LIMIT` | 계정 한도 — 깨움 셈에서 빼고 한도 상태 파일 · 사람 로그인 청 |

- 알림은 `wake_owner` 에게 먼저, 10분 뒤에도 그대로면 창구에게.
- 빼는 목록: 사용자 답 기다림 · 대기열 「대기(…)」 · 일부러 멈춤 · 감시 중 · 문지기 표지.
- 지표(칸 수 · 일하는 비율 · 막힘 시간 · 오보 · 규칙 어김)를 칸 · 하루 기준으로 모은다.

## 대기열 파일
칸마다 하나(`templates/queue.md`): 지금 일 · 다음 걸음 · 대기(무엇을 기다림 · 막힘 아님) · 지난 일(이어 붙임). 기록 대본이 칸 장부의 work 칸도 함께 고친다. 「대기(…)」 로 적은 칸은 정상 기다림으로 보고 재촉하지 않는다.

## 지시 장부 · 훅 강제
- 프롬프트 제출 훅: 창구 꼬리표가 붙은 사용자 말을 지시 장부에 자동으로 넣는다.
- 멈춤 훅: '받음' 상태 줄이 남아 있으면 그 턴을 끝내지 못하게 막는다. 증거 칸이 비면 '끝' 보고를 못 한다.

## 창구 감독 바퀴(`wake_owner: desk` 일 때)
| 바퀴 | 주기 | 대본 | 하는 일 |
|---|---|---|---|
| 깨움 | 2분 | `tools/idle_escalate.py` | 원격 작업자 `idle_min` 넘게 쉬면 깨움 · 30분 안 두 번이면 사용자 보고 · 사건 장부 |
| 화면 | 4분 | `tools/check.py` | `hc get` 상태 + 원격 화면 판정 + 진행표 나이 → 멈춤이면 그 PC 감독 칸에 근거 한 줄 · 10분 넘으면 지휘 |
| 판 | 30분 | `tools/board_report.py` | 원격 시나리오 판 모아 완료율 · 이전 대비 · 막힘을 표로 |

## 판정 사다리
1. `hc get` 이 working → 통과
2. blocked · 확인 창 → 사람 몫이면 사람에게(`--force` 로 넘기지 않음) · 한도는 '계정 한도' 갈래
3. 진행표 · 대기열이 10분 안에 바뀜 → 일하는 중(턴 사이)
4. 빼는 목록 → 통과
5. `idle_min` 넘게 쉼 → 깨움(깨우는 글: 「대기열 다음 줄 바로 · 진행 한 줄 · 못 하면 [막힘] 까닭 한 줄」)
6. 30분 안 두 번째 깨움 → 사용자 보고 + 사건 장부

## 사건 장부(선순환)
- 틀: `templates/idle-incidents.md`. 한 줄 = 시각 · 갈래 · PC · 칸 · 까닭 · 조치 · 규칙 반영.
- 갈래: 계정 한도 / 원장 있는데 대기 / GO 기다림 / 로그인 · 인증 / 짝 PC 기다림 / 사람 손 / 판정 잘못 / 감독 칸 멈춤 / 깨움 예약 사라짐 / 복구 뒤 주소 엇갈림.
- 총괄이 6시간마다 갈래를 세고, 같은 갈래가 두 번이면 규칙 · 스킬 · 대본을 고친 뒤 다음 6시간에 줄었는지 본다.
- 감독 판정이 틀린 것도 갈래로 적고 판정 기준을 고친다(예: 진행표 3분 → 10분, 화면 글 → `hc get` 상태).
- 묶음마다 가장 느린 걸음 셋을 적어 다음 묶음에서 줄인다.

## 한도 · 개발 중단
- 한도에 걸린 칸: 한도 상태 파일에 멈춘 칸 · 초기화 시각 · 멈춘 자리 · 원복할 것.
- 계정을 바꾼 뒤: 옛 한도 창에 Esc → 재개 글. 원격 PC 는 따로 로그인해야 한다.
- 사용자가 '개발 중단' 을 말하면 칸마다 멈춘 자리를 쓰고 스스로 다시 시작하지 않는다.
