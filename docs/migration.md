# 이관 · 인계 · 모델 전환

## 표시 앱 이관(예: TUI · 다른 작업공간 도구 → Herdr App + Core)
1. 옛 상태에서 명부를 만든다(칸 · 대화 id · cwd · 모델 · effort · 레인).
2. 대화 id 마다 대화 기록 파일이 **정확히 하나**인지 먼저 검증한다(0 이나 둘 이상이면 멈춤).
3. 정책 · 스킬 · 전역 지침은 사본을 남기고 고친다.
4. 운영 변경 글을 붙여 같은 id 로 재개하고, 앱 명령(`space.new` · `terminal.keep` · `pane.split`)으로 배치를 다시 세운다.
5. 옛 진입점은 새 앱으로 돌려 같은 id 가 두 번 뜨지 않게 한다.
6. 결과 파일 · 실패 목록을 남긴다. 같은 원인 실패 3회 상한.

## 총괄 소유권 인계(ACK)
1. 공지: 누가 · 무엇을 · 언제부터 넘겨받나.
2. 수신 기록: 받는 쪽이 공지를 읽었다는 줄.
3. ACK 줄(`templates/handoff.md` 「ACK」): 받는 칸이 **읽기만 하는 턴**으로 자기 대화 id 와 실행 인자 대조 · 레인 HEAD 와 git status · 다음 한 동작(실행하지 않음)을 보고.
4. ACK 전에는 넘겨준 쪽이 계속 주인이다. 같은 작업자를 두 관리자가 동시에 지휘하지 않는다.

## 다른 모델 사이 전환(예: 에이전트 A ↔ 에이전트 B)
- 모델 사이에는 재개가 안 된다. 원래 기록은 보존하고, 사람이 읽을 수 있는 대화 문서(목표 · 결정 · 지금 상태 · 남은 일 · 함정)를 만든다.
- 새 세션 id 를 미리 정하고, 첫 턴은 인수 확인만 한다(ACK 와 같은 꼴).
- 상대 모델의 id 를 재개 id 로 쓰지 않는다.
- 권한 생략 실행 모드라고 사용자 제약이 풀리지 않는다 — 규칙 파일 · 허락 범위를 같이 넘긴다.

## 계정 바꿈
- 같은 대화 · 같은 레인으로 잇는다(H-9). 옛 한도 창에 Esc → 재개 글 → 깨움 예약 다시 걸기.
- 원격 PC 는 따로 로그인해야 한다.
