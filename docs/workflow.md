# 일의 흐름

```
사용자 말 ─▶ 창구(원문 기록 · 지시 장부 · 전달) ─▶ 총괄(단계 · 맡은 칸 · 끝 근거 · 지시서)
   ─▶ (필요하면) 설계 칸 · 결정 매니저
   ─▶ 구현 칸: 레인 열기 → 빨강 시험 → 고침 → 초록 → 커밋 → 준비됨(리뷰 줄 포함)
   ─▶ 리뷰 칸 둘(새 맥락 · 정확성 / 보안) → 고칠 것 있으면 같은 레인으로 되돌림
   ─▶ 병합 칸: 빌드 자리 GO → 준비된 레인 묶음 → 저장소 시험 전체 한 번 → 기준 판과 실패 대조 → 병합
   ─▶ 판 올림 → 키트 · 이미지 내용 관문 → 같은 판 설치기 → 설치 검증 → push · 태그 · release(허락 범위)
   ─▶ CI → 배포 가지 PR → CD → 실제 확인
   ─▶ 원격 시험 지휘: 키트 확인 묶음 → 원격 PC 들
   ─▶ 결과 · 결함 → 총괄 → 새 레인(선순환)
```
매번 전 단계를 형식적으로 되풀이하지 않는다. 실패 원인이 가리키는 단계로 돌아간다.

## 단계별 끝 근거
| 단계 | 끝 근거 |
|---|---|
| 레인 | 커밋 해시 · 빨강/초록 시험 이름 · 결과 · 리뷰 줄 |
| 리뷰 | 리뷰 결과 파일(통과 / BLOCKER · MAJOR · MINOR n) · 다시 볼 때는 같은 파일 끝 절 |
| 묶음 검사 | 시험 수 · 실패 0(또는 기준 판과 같은 실패 이름만) · 검사 시간 |
| 병합 | 병합 커밋 · 판 번호 |
| 키트 · 설치기 | 파일 해시 · 이미지에 시험 스텁 0 · 깨끗한 설치 / 덮어 설치 / 제거 · 다시 설치 결과표 |
| push · release | 원격마다 sha · 트리가 같음 · 태그 · 자산(설치기 · 해시 · 서명) |
| CD | 배포된 판 번호를 실제 서비스에서 읽은 출력 |
| 원격 | 시나리오 판 완료율 · 결과표 · 그림 |

## 레인 원칙
- 같은 파일을 여러 레인이 고치지 않게 총괄이 조율한다.
- 묶인 레인에는 커밋을 더하지 않는다(고칠 것은 새 레인).
- 레인마다 따로 시험을 돌리면 줄이 밀릴 때는 묶음 검사 하나로 겸한다(검사 범위는 줄이지 않음).
- **리뷰 줄이 없는 레인 보고는 병합 칸이 거부한다.** 리뷰는 구현 대화와 다른 맥락에서 하고 리뷰어는 구현 파일을 고치지 않는다.
- 시험 · CI 파일만 바꾼 레인은 스스로 병합할 수 있고, 제품 코드는 총괄 리뷰를 거친다(설정으로 바꿀 수 있음).

## 빌드 자리 · 병합 차례
여러 프로젝트가 한 PC 메모리를 나눠 쓴다.
- 무거운 일(빌드 · 전체 시험 · 화면 시험)은 모든 대화를 통틀어 **한 번에 하나**. 자리를 쥔 칸(병합 칸)이 GO 를 준다.
- 시작 선 · 멈춤 선은 남은 commit 메모리로 정한다(설정 `build_slots`, 예: 빌드 하나 ≈ 7GB · 시작 문턱 10GB · 켠 뒤 여유 4GB 아래로 갈 일은 켜지 않음). 칸 수 상한과 같은 근거를 쓴다.
- 시작 · 끝 줄을 차례표에 이어 적는다. 남에게 넘긴 자리는 20분 상한으로 기다린다. 무거운 일 뒤에는 캐시를 비운다. 긴 회귀는 시간대를 따로 잡는다.
- 실패 이름을 기준 판과 대조해 **새 실패 이름이 있으면 병합하지 않는다.**

## CI/CD
- CI 통과 → 배포 가지로 PR → CD 배포 → 실제 확인까지가 한 일이다.
- CI 가 도는 동안 push 하지 않는다(CI 가 취소된다). 같은 원인 실패는 H-10 상한 · 고치지 않은 재실행 금지.
- 배포를 부르는 병합은 G-6 따로 허락.
- 함정: CI 잡이 띄운 프로그램은 잡이 끝나면 같이 죽는다(상주 프로그램은 서비스 · 예약 작업으로). 릴리스 본문을 API 로 올릴 때 UTF-8 이 깨질 수 있다(파일로 넘긴다).

## 총괄 상시 루프
- 회차 간격을 정하고(설정 `lead_loop_min`), 회차 처음에 목표 파일 · 지시 장부 · 감시견 경보를 읽는다.
- 0단계(간격과 상관없이 바로): 막힌 GO · 기한 지난 지시 · Core 재시작 감지 · `error` · `blocked` 칸 · 죽은 셸 · 끝 조건이 아직 거짓인 '진행' 줄.
- 끊긴 줄은 그 줄의 「끊기면」 대로 잇는다. 바뀐 것이 없으면 보고하지 않는다.
- 하루 한 번 감사 칸(또는 리뷰 칸)이 '끝' 줄과 증거를 맞대어 「어긋남 · 증거 없음 · 확인 못 함」 으로 나눈다.

## 프로젝트 사이
- 계획 전에 상대 담당에게 「지금 있는 것」 을 먼저 묻는다.
- 계약 변경 알림은 sha 마다 한 번 · 맞물리는 계약은 협의 문서 합의 뒤 착수 → [structure.md](structure.md) 「정보가 흐르는 길」.
